## Behavior and contracts

`ReviewReply(answer, changes)` and `ReviewProvider.review(request)` are exported publicly. OpenAI review uses one structured call through the existing `BudgetedStructuredTransport`, the existing session budget, trusted SDK usage accounting before payload validation, and the provider's disabled SDK retries. The separate changes schema permits only `FileChange` fields; validation rejects outside selection, false base hashes, malformed or duplicate changes. Proposal IDs, selected paths, and workspace association come from local captured context and C1 services, never model metadata or Markdown extraction.

`ReviewService(analysis, provider, patches, history).review(request, *, cancel=None)` returns `ReviewResult(analysis, advice, proposals)`. Analysis runs off the event loop with one action cancellation Event; repeated task cancellation waits for actual worker completion and preserves cleanup failures. Without a provider, review returns local AST/Ruff findings without advice, proposal persistence, or history success. With a provider, local findings and the refactoring guidance enter the policy-prepared request; suggestions preserve API/behavior, explain tradeoffs, and avoid unsupported optimization. All candidates are preview-validated before proposal persistence. Review never applies a patch or runs project pytest. History uses the existing metadata/reference/digest-only repository behavior; C2 does not restore verbatim response storage.

`VerificationService(runner, *, store=None).run(proposal, workspace, *, checks, cancel=None)` returns `VerificationResult(status, checks, sha256)`. An empty selection returns `unverified` even for an unapplied proposal. Explicit nonempty checks allow only `ast`, `ruff`, and `pytest`, require current UTF-8 bytes to equal the proposal's after-text SHA-256, capture selected sources afresh, and revalidate the same snapshot after checks. Argv is constructed locally without a shell. Ruff uses isolated configuration and no cache. Pytest discovery runs in the resolved workspace root only when explicitly selected; it executes project tests/conftest with the user's privileges. Current-run JUnit must record successful, nonempty, non-skipped tests. Failures, absent/malformed JUnit, missing tools, truncated output, timeout, and cancellation cannot pass. Temporary JUnit/cache files use B2's external allocation logic, which rejects project-local temporary paths before probing or allocation.

`VerificationStore(data_dir)` persists workspace/proposal-associated results under opaque hashed keys, with atomic replacement and private state modes on POSIX. `VerificationService.current()` returns `unverified` when the applied file has changed or the saved result does not match its current digest. Project checks do not create learner approval evidence. The optional store preserves the positional runner API; C4 must inject it for runtime persistence and run this synchronous verification API off the event loop with its action Event.
